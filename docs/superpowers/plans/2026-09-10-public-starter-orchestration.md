# 公开起步方案：执行编排与报告实施计划

**Goal:** 将已有 starter 模块串成 N/R 单套件执行入口，以及只读产物的离线报告入口。

**Architecture:** 每个进程只处理一个 suite × track × mode，独占新 run-dir。N 使用显式模型客户端；R 使用独立 runtime，复用原生导入、Ask 与上下文捕获。先写计划和身份，逐题保存输出，再逐项评分，报告只读产物。

**Spec:** [起步方案](../../deepeval-public-starter-plan.md)与[首批代码交接](../../deepeval-public-starter-implementation.md)。继续采用 executing-plans；已有用户授权，无需重复设计确认。

## 约束

- 本轮仅写代码与文档，不运行脚本、不导入新模块、不执行测试、不下载数据、不调用模型。
- 继续现有开发分支，生产代码只读；旧 baseline/timer 不变；不新增发布质量阈值。
- 无隐式重试/续跑，已有运行目录拒绝覆盖；客户端内部重试单独记录。
- N 与 R 不合并分数；无输出/缺失上下文/缺少规则审计分别记录。

## 文件和任务

1. `starter_runtime.py`：独立进程环境配置；复制产品服务配置到私有 runtime，避免运行时热加载生产变更；显式 native/judge 配置解析；源码、依赖与模型身份快照。
2. `starter_runner.py`：本地冻结输入和人审载入，固定同集干扰库；创建计划；N 逐题预测和原生 scorer；R 原生导入/Ask、BoolQ 结论/GEval/Faithfulness、最终证据覆盖；失败留痕并生成状态。
3. `run_public_starter.py`：必填 track 与输入的新 CLI；单进程一次一个 suite/mode；无默认 all 批量在线动作。
4. `starter_report.py` / `report_public_starter.py`：从计划、输出、评分和状态生成 JSON/Markdown；报告缺失、错误、解析覆盖、各类能力及案例路径；分开展示 N/R；仅满足配对身份的 chunk/reasoning 逐题并列。
5. 模型配置示例和交接文档：解释哪些入口将调用模型、哪些仅离线分析；明确尚未执行或验证。
