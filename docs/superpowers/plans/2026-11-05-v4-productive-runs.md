# V4 productive, slow-service-tolerant runs

Goal: user-authorized smaller ALCE-ASQA experiment that produces useful candidate iterations without premature local timeout exits. Preserve score/gold boundaries and adoption arithmetic. No live local experiments.

Architecture: optional adapter waiting mode treats positive running status as ongoing work under the optimizer's total deadline; unknown/error states stay bounded. Coordinator gains explicit control over predictive early stop and bounded replay of required failed measurement steps. Agent briefs encourage small, evidence-supported experiments, not fabricated support. Experiment: 60 optimization cases, 36/24 paper split, 4 cards/round, b2, one actual evaluation at a time, 4 partitions x4 prep workers, model gate16; 12h optimization; independent sealed remains separate.

1. Adapter: optional wait_for_running setting, retain V3 behavior by default, tests for slow running Agent/eval, unknown timeout and total cancellation. Long external execution/partition deadlines for this experiment; cannot redefine remote service request deadlines as infinite.
2. Coordinator: configurable predictive stop (default preserved), bounded required-measurement recovery with durable request identity and no retry-by-score; no blanket retry of analysis/messages. Tests for recovery, bounded persistent failure, total budget and resume. Inspect actual generation contracts before choosing implementation.
3. Briefs: limited answer-path/source-supported hypotheses; unconfirmed causality may lead to implement/inconclusive; prioritize cheap tests and new learning after no adoption; preserve no arbitrary cards, score gaming, or validation leakage.
4. Delivery: smaller deterministic pool independent of scores; explicit model/time policy; standard iteration/service entry, dedicated config/state/output and correctly pinned Python module source for UI. Server preparation/cache identity checks; reuse immutable artifacts/cache only when verified. Current experiment flags/deviations documented. Regression, review, commit/push, private package with complete SHA and instructions.

Acceptance: slow reported-running work can outlast local timeout but not the total budget; unknown task status remains finite; no old generation silently rewritten; failures preserve artifact evidence; 60-case selection cannot overlap heldout pool; nonadoption does not require fabrication or lowering statistical safeguards. No performance improvement claim before independent endpoint evaluation.

Implementation decisions after inspection:
- Reuse RoundMeasurements' existing bounded infrastructure retries (`infra_retry=2` in delivery) instead of adding coordinator replay. `_advance` persists retry generations and request keys; `_infra` excludes still-running and explicitly cancelled work. A second whole-loop retry would duplicate this policy and require resetting sibling cancellation state. Exhausted required seed/parent measurement still halts; candidate-local failures remain isolated up to the configured consecutive-failure threshold. No automatic key-generation bump.
- Add `predictive_time_stop` with historical default true. Its default is omitted from the config digest so old v4-state-3 identities remain resumable; false is hashed and reported as a method variant.
- `wait_for_running` defaults false. Enabled waiting requires a configured total-runtime callback. Unknown Agent status or failed observation is not proof of running, so each continuous observation gap has its own bounded local timeout; confirmed running resets that gap window. A positive running status is also not proof of useful progress: a hung-but-running Agent can use the total budget. Bridge RPC and model-client request timeouts remain separate finite boundaries.
- Delivery uses model gate 8 (within both reported service limits), four partitions and four preparation workers, one execution at a time. Only one-partition throughput has been measured; multi-partition throughput remains to be verified on the server. External execution/case/partition deadlines are 24h, beyond the 12h optimizer budget even with executor cleanup reserve; the optimizer owns cancellation at its total budget.
- Keep calibration k=2 and let measured noise select candidate k=1 or 2. Keep original adoption/reviewer thresholds. Disable merge, ablation and speculation in this first continuous run; use one runtime smoke case and no behaviour gate. Six no-adoption rounds and eight rounds maximum leave more room for revised hypotheses than the default three.
- Select 60 of R3's 250 unsealed cases by a fixed case-ID hash, independent of scores. Register the existing 98 heldout cases for visibility protection but do not authorize endpoint execution. These 60 are development data, potentially already used in R3. A later independent endpoint requires auditing historical access across old states, not merely a new state directory.

- Include partially correct search answers in analyst failure selection (score < 1.0) and raise its evidence-file budget to 60000 characters. This affects diagnosis only, not score calculation or adoption. Rendering omissions must still be observed on real traces.

- Delivery review found two inherited helper issues: local evaluator workspaces were excluded by the candidate-worktree-only list API, and a pending root could not be reconciled after initial setup. Use the bounded raw CLI list (all isolation types), and replay the fixed creation receipt with immutable input checks; never create a new experiment to recover slow provisioning.
