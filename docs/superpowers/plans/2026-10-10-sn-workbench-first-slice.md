# SN 工作台开发顺序建议

2026-10-11 修订。本文提供可调整的责任划分和推进顺序，不冻结目录、接口命名、组件数量或切片边界。实现中以完整工作路径和反馈调整；无需等所有界面与技术细节定案。

**目标：** 在单服务器上逐步走通“打开 SN workspace → 建立任务 → 手动或 Agent 拟定题单 → 运行评测 → 读成绩与证据 → 调查和人工判断 → 修改与验证 → 回访历史”。

**当前推荐：** 前端尽量采用 Paseo 的技术及界面经验，Agent 能力优先复用 Paseo，评测计算保留 Python 与现有工件。独立 Web＋公共 SDK 是目前的起点，插件或其他接入形式仍可结合实施成本调整。

配套：[PRD](../../evaluation-improvement-workbench-prd.md)、[技术方案](../specs/2026-10-10-evaluation-improvement-workbench-design.md)、[交互参考](../../product/sn-workbench/interaction.md)、[接口草案](../../product/sn-workbench/api-and-events.md)、[选型参考](../../product/sn-workbench/technology-decisions.md)。

## 尽早形成可用工作面

建议先做 workspace／任务导航、Agent 会话、输入框和右侧材料，导入一份已有结果即可阅读，不必先建齐所有后端模块。这样可以较早看见真实信息密度，并在开发中调整布局、任务与会话关系。

接入早期可以用明确标记的构造数据展示未完成部分，再逐步替换为真实查询与执行；不能把构造状态当作已完成能力。技术兼容问题在相关入口解决，不先形成一套孤立的服务空壳才开始界面。

## 责任划分参考

| 责任 | 建议位置 | 实现时重点 |
| --- | --- | --- |
| 路由、导航、会话、材料与共享控件 | `apps/sn-workbench/` | 参考 Paseo 的组织与组件，目录随实际代码规模调整 |
| Paseo 能力适配及必要的同源接入 | `apps/workbench-gateway/` 或所选集成入口 | 公共 SDK、事件恢复、Agent 生命周期；是否独立网关在接入时确定 |
| 可共享的数据定义 | 前端／接入层的 contracts | Zod 是候选，不要求一开始单建完整 package |
| 任务、计划、作业、历史与人评 | `src/rag_eval/workbench/` | 共用应用操作，复用既有读取、运行与比较能力 |
| 执行适配与运行来源 | Python runner 边界 | 固定题单、真实源码、独立 attempt、生成／评分事实 |

这些路径不是逐文件施工清单；相近职责可以先集中，真实需求增长后再拆分。

## 建议推进路径

### 1. 会话工作面与已有结果阅读

- 建立能直接使用的 workspace／任务工作面，先参考 Paseo 的导航行、标题栏、时间线、输入框、主题和材料面板。
- 尝试接入可用 Agent，导入已有结果；连接不可用时仍能读成绩和证据。
- 记录实际兼容依赖，参考 Paseo 版本而非逐项强制匹配；局部选型可调整。
- 观察真实材料的密度、阅读顺序及面板切换，再调整页面。

阶段结果：用户能进入任务、开始协作、阅读一份真实结果；尚未完成的执行动作明确说明状态。

### 2. 选题、计划与评测执行

- 复用 bundle 与现有配置入口，保存具体 case IDs、完整资料范围和实际执行配置。
- 将手动与 Agent 提交接入共同应用层，返回可查询的计划与作业引用。
- 建立作业监控，分别呈现生成与评分、部分输出及取消回执；HTTP 查询失败不自动重新运行。
- 在 runner 边界确认源码捕获与真实加载位置。可先使用 clean 对象，也可在此补 dirty 捕获；依据当前工作路径决定，不永久禁用未提交改动验证。

阶段结果：用户知道测了什么、实际运行哪个版本、哪些结果已完成，并能重新打开任务。

### 3. 证据、判断与持久历史

- 复用正式分数、逐指标分母、覆盖和已有证据读取，不在前端重算官方汇总。
- 就近保存人工判断，绑定具体答案和版本；其他评审者记录与历史修订保留。
- 切题、切任务和异步更新不覆盖当前材料或输入；再次打开能恢复服务端保存的记录。
- CLI 与界面使用同一业务记录；导出与重建跟随实际使用补齐。

阶段结果：能从分数进入真实案例，保存判断，回到当时的结果和记录。

### 4. Agent 工具与动态领域内容

- 根据已接入 provider 的真实能力选择 MCP 或其他领域命令适配，复用前面的计划、查询及取消操作。
- 把计划、进度、结果和待决事项自然融入会话；卡片、行内结果和材料链接可在界面中调整。
- 会话历史与领域事件分别恢复，Agent 停止／替换不自动取消作业。
- 保留已有委托及执行回执，减少重复操作；未知能力如会话导入在需要时核对。

阶段结果：Agent 与用户都能开展同一评测流程，用户无需逐步手工接力。

### 5. 调查、修改与验证闭环

- 从一份结果提取问题及证据，加入候选原因、反证和可执行方向；证据不足时保留未决。
- 关联真实改动及被测版本，允许沿用当前 worktree 或其他适合的执行方式。
- 复用既有比较器呈现完整成绩、适用的逐题变化、退化和成本。
- 分别保存观察到的效果与原因判断，让结果能够否定原建议。

阶段结果：用户在一个任务中完成评测、调查、修改和验证，不要求必须先跑完全部 benchmark。

步骤可以穿插，例如会话接入与结果阅读一起做，源码捕获随着修改流程提前补齐。首个可交付范围以开发时实际走通的路径报告，不由本稿预设 clean-only 或固定 Task 1~7。

## 实现阶段按风险核对

当前设计阶段不运行下列检查。实现相应边界时，再做能发现真实问题的验证，不机械为每个组件生成测试。

| 边界 | 值得核对的情况 |
| --- | --- |
| 成绩与材料 | 有效零分／缺失、批量汇总、同答案多评分、错误来源与重复导入 |
| 提交与执行 | 提交回执丢失、重复请求、取消与完成竞争、API／worker 中断 |
| 源码与修改 | 已有 dirty 内容、外部并发编辑、实际加载版本与捕获内容不一致 |
| 界面与事件 | 断连漏历史、切题后迟到响应、阅读位置与输入保持、真实长材料 |
| 人评与历史 | 保存失败、同记录流冲突、多人并列、旧版本可打开 |
| Agent 接入 | provider 差异、会话替换、工具回执、停止会话而作业继续 |

既有评分来源、真实状态和生成不见 gold 的要求继续保持。新增目录和原型不扩大 CURRENT_STATE 的实际实验范围；真实模型运行按明确任务执行，不以开发计划自动启动。安装、测试及部署在真正进入对应实现工作时安排。
