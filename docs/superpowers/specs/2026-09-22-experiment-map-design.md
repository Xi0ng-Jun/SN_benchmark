# 实验地图与单题回放设计

用户已批准上一轮设计并要求实施。首版围绕 QMSum 贯通 chunk/reasoning/BM25，同时保留现有数据格式的筛选和浏览。只读本地工件，不运行 SN、judge、下载数据或修改实验结果。参考 Learn Git Branching 的对象身份、操作与状态联动和可分享场景；不复制 Git 模拟器或引入在线执行平台。

## 用户验收

开发者打开页面即可知道哪些实验完成、用了什么资料和配置、哪些回答被重新评分。选题后能沿流程前进/后退，点击节点查看实际输入、输出、字段说明、产物和代码位置；展开真实原生 span 看具体动作及组件分。同题比较能回到两边记录。复制链接保留选定 run/case/step/view。示例必须标注为构造数据，不能冒充服务器结果。

## 数据边界

页面首页展示数据来源→运行→答卷→评分批次的关系。数据共源用冻结 source 身份；重评分连线依赖 scoring_batch.origin_manifest_sha256 与原始答卷文件哈希，不按目录名猜测。来源 run 未提供时显示外部来源节点，不自动读任意磁盘路径。问答数量不因 objective/native 多指标或重评分副本重复增加。

流程阶段分为 observed（存在实际输出/观测）、recorded（静态协议/冻结工件证明）、missing（未保存）。未有时序只作逻辑浏览，原生 span 才展示实际时间；不拼造调用树。完整轨迹原样保持父子身份；SDK 的评分前/结束快照择最终状态，组件样本按 request_id/sample_id/span_id 精确关联。N/A、error、missing 与 0 分分开。

首次只把摘要放入 dashboard-data.json/HTML，逐题完整内容保存为 details/<observation_id>.js，点击后用本地 script 加载；无需网络/CDN/后台，file:// 可打开。JS 包装只携带 JSON 数据，文本通过 textContent 渲染。选题异步加载用选择版本号防止旧请求覆盖新选择。真实 JSON 不裁剪，题目预览截短只作用于摘要。导出目录仍必须独立且新建，结构化密钥脱敏。

## 三层界面

1. 实验地图：数据/运行/答卷/评分节点，执行状态、数量与配置，明显的模式颜色；可切换 suite 和 run。选节点会切换同一选择状态。
2. 单题流程：横向阶段图、播放/暂停/前后/重置；右侧用途、输入、输出、字段解释、代码/产物四类详情；原生调用树可展开、选 span 后对应分数联动。gold 只在原题/评分详情，不画进导入或 SN 上下文。
3. 结果分析：动态组合标签、分布/覆盖/均值、保存比较组、配置差异、同题配对、点题追溯。objective 使用冻结资料/题目/指标验证；native 额外要求 judge/protocol 对齐。组件有多次调用时只展示分布，不伪装成逐题一对一配对；没有匹配必须说明原因。

不默认过滤失败；生成数、成功回答数、评分条目数分别展示。没有单一跨指标总分。旧纯摘要也可浏览，缺 trace 显示未采集；不迁移旧 Agent 分，不声称已覆盖所有历史格式。

## 实现分工

Python 负责读取/验证/归属/索引，纯 JS 负责筛选/比较/URL 状态，DOM/SVG 负责图形和详情。继续复用现有 load_run 与指标说明，取代当前页面布局；不保留两套 dashboard 页面。生成器逐 run 处理大工件；浏览器按题加载完整数据。
