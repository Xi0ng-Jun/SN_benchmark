# 十套公开 Benchmark 的任务与选题方案

> 历史设计：本页记录选题和分库方案，尚不等于当前数据已冻结或 runner 已完整实现。


日期：2026-09-14。状态：设计已沉淀，尚未按本方案准备数据或实施代码。

用户明确：规模不设预先上限，重点是怎么选、选哪些。本方案替代此前“每套 20 题”“每类前 5/10 题”的预算建议。当前只整理文档，不测试、不运行实验、不下载或冻结数据、不启动 SN、不调用模型。

## 1. 选题目标与范围

主要评测对象是 Silicon Notebook。先复用 DeepEval 支持的公开 benchmark 数据与评分，再按结果考虑产品业务场景和 Agent 过程评测。Native 模型参照与 SN 系统结果分别保留。

先确定需要观察的能力，再确定 suite、task、split 和纳入规则；题数由这些规则覆盖的数据自然决定。对选定任务取完整的符合条件数据，不按固定题额、原顺序前缀、答案标签比例或模型成绩裁剪。不预先填写总题数，也不把历史 smoke/baseline 样本数当成新方案配额。

任务范围仍有明确取舍：MMLU 先覆盖四个学科，BBH 先覆盖四类推理。这些选择沿用上一轮建议，属于本阶段的能力范围，不是为了限制题数；剩余任务列为未覆盖，后续扩展另记版本。数量不限也不意味着当前已授权执行这些数据。

## 2. 十套评测分别选什么

以下 dataset/split 沿用当前仓库的数据契约。实际源文件、不可变 revision、许可、导出方法与样本身份需在未来准备阶段核实并冻结；当前没有下载数据，因此不宣称已得到完整数量。

| Suite | 数据与选定任务 | 纳入范围 | 对 SN 的主要观察 | 解释边界 |
|---|---|---|---|---|
| SQuAD | `rajpurkar/squad`，validation；`Normans`、`Steam_engine` 两个文章主题 | 两个主题下全部原题及配套段落 | 资料中的事实定位与回答；历史人物和技术说明两类文本 | 两个主题不代表整个 SQuAD 或半导体领域；原文中的答案是合法证据 |
| DROP | `ucinlp/drop`，validation；history、nfl 两类 section | 两类中全部 section 的原题，不要求 section 至少有十题；产品评分保留完整原始答案注释要求 | 在资料中提取信息并进行数值、日期或离散推理 | 答案类型不等于推理操作；多个 span 的局部命中不代表完整回答 |
| BoolQ | `boolq/default`，validation | 完整 split 的全部原题，保持自然 Yes/No 分布 | 根据资料判断一个说法是否成立 | No 是正常答案，不是拒答；不能由标签匹配判断解释质量 |
| LogiQA | 当前契约指定的 `csitfun/LogiQA2.0` 仓库 `logiqa/DATA/LOGIQA/test.txt` | 必要条件、充分条件两类任务的全部记录，分别保存原题与任务归属 | 基于资料条件进行逻辑判断 | 仓库名不等于实际数据版本；按源文件身份记录。答对选项不证明推理过程正确 |
| GSM8K | `openai/gsm8k`，test | 完整 split 的全部原题 | 理解文字题条件并计算 | 题面自身包含条件；不是检索召回质量测量，也不证明现实单位换算全覆盖 |
| BBH | `lukaemon/bbh`，test；下节列出的四个 task | 每个选定 task 的完整数据 | 条件推断、日期理解、计数、状态跟踪 | 分 task 报告，不能泛化为全部 BBH 或 Agent 工具能力 |
| MMLU | `cais/mmlu`，test；下节列出的四个 subject | 每个选定 subject 的完整数据 | SN 流程处理不同学科知识题的表现 | 题面与候选项不提供独立知识证据，不代表资料事实检索能力或专业资格 |
| TruthfulQA MC1 | 当前契约的 `truthfulqa`，validation，multiple-choice 配置 | 完整 split 中具有合法 MC1 注释的原题，纳入全部可用主题 | 在包含常见误解的选项中识别正确答案 | 只评 MC1；不等于开放式诚实性、基于资料的忠实性或正确拒答率 |
| HellaSwag | `Rowan/hellaswag`，validation | 完整 split 中有公开标签的原题，保留全部活动类别 | 判断与情境相符的后续发展 | 候选续写不属于已发生事实；不构成资料引用正确性的真值 |
| IFEval | `google/IFEval`，train | 完整 split 的原始 prompt 及全部 instruction/kwargs，不因 verifier 支持不足删题 | 格式、长度、内容等指令与多约束遵循 | split 沿名不变；直接使用固定版本 DeepEval verifier，不要求额外人审，不冒充原论文 strict/loose 口径 |

保留公开数据提供的参考答案。缺字段、类型错误、来源不明等记录需要隔离并报告，不能静默跳过后声称覆盖了完整 split。若发现来源或格式与本表契约不一致，记录差异并明确更新版本，不能按名称猜测转换。

## 3. MMLU 与 BBH 的具体选择理由

### MMLU

| 官方 task ID | 为什么选 |
|---|---|
| `high_school_computer_science` | 覆盖技术概念和计算机知识，接近技术学习类 notebook 的通用任务 |
| `high_school_physics` | 覆盖自然科学概念、条件理解与推断 |
| `high_school_world_history` | 覆盖人文事实、人物事件和时间背景，减少只测理工知识的偏向 |
| `high_school_macroeconomics` | 覆盖社会科学概念及关系判断 |

这四科各自使用全部符合规则的 test 题目，不要求等量。先分别报告各科表现和样本数；如展示跨科平均，明确区分按题目加权和学科等权，不把四科平均称为完整 MMLU 分数。暂未纳入的其他学科没有成绩，不能用这四科填补。

### BBH

| 官方 task ID | 主要观察 |
|---|---|
| `logical_deduction_three_objects` | 从多个约束中推导对象关系 |
| `date_understanding` | 理解日期、相对时间与时间推断 |
| `object_counting` | 从描述中识别对象并计算数量 |
| `tracking_shuffled_objects_three_objects` | 根据连续交换跟踪最终对象状态 |

这些 task 提供相互区别的推理场景。已有 GSM8K 覆盖文字算术，所以首版不优先重复加入 BBH 纯算术任务。五对象、七对象版本、其他逻辑与语言任务保留为后续范围扩展，不与三对象任务混称。各 task 的输出域沿用对应适配规则，不能统一抽取正文最后一个数字或字母。

## 4. 数据怎样进入正式题单

1. **先冻结范围。** 记录本表 task、split、来源 revision、选择规则版本及用途；这一步必须发生在查看 SN 答题成绩之前。
2. **按范围枚举全部原始记录。** 保存上游样本 ID 或原始文件行号，以及本地导出行号与内容 hash。对按学科分文件的数据，分别保留文件身份和文件内顺序，合并顺序明确固定。
3. **校验原始注释和结构。** 合法题目保留原文与参考；问题样本进入异常清单。记录错误原因、数量和身份，修复转换错误后重建；不通过删除异常行伪装成全量准备成功。
4. **记录覆盖分布。** 按源数据已有主题、标签、答案类型、task 和指令类型统计。没有元数据时标为未知；模型辅助分类只能作为候选标签，不用于无记录地筛题。
5. **分别判断产品适用性与评分可用性。** 前者涉及题目在产品输入中的含义，后者涉及评分方法是否可靠，两者不合并成一个删除开关。
6. **形成不可变题单。** 保存完整纳入、排除、待审、异常清单。后续出现答错、解析失败、拒答或澄清时，保留在运行计划和结果分母中，不据此更换题目。

### 审核规则

- SQuAD/DROP/BoolQ 沿用已有人工适用性审核。例如跨段落检索时指代对象不清，应记录真实审核结论；待审题仍属于选题清单，但暂不进入其旧版 R 执行计划。不能自动填入 approved。
- DROP 的完整原始注释是产品评分的必要输入；SDK 扁平 span 不足以替代。缺失时保留题目、记录资料缺口和产品 N/A，不能为了有分数而降低完整性要求。
- LogiQA 和其他新七套按原字段构造系统输入，不新增虚构的人审前提。实际产生的澄清是输出观察，不能自动作为选题错误、能力失败或删题理由。
- IFEval 保留所有原题与完整 instruction ID/kwargs，直接逐条调用固定版本 DeepEval verifier；整题所有指令通过为 1，否则为 0，不因未人工审核而跳题或记 N/A。包括默认分支在内均遵循 SDK 实现。v1 冻结 inventory/pending 为兼容保留，不是执行门槛，详见 [直接评分说明](ifeval-direct-scoring.md)。
- TruthfulQA 导出若没有 category，记录“主题未知”；不能由答案内容猜主题后宣称覆盖了某个类别。MC1 候选项与标签映射保持原契约，选项排序继续使用已固定的方法。

原题、原文、选项和参考答案不翻译、不改写。补充条件、修改问题或另选主题，都需要独立版本与理由。分布不均衡应公开呈现；本版不通过标签配平或挑题来制造均衡。

## 5. 题目数、任务记录数与材料去重

需要同时保留三类身份：原始记录、独立问题、任务归属。LogiQA 同一道原题可能属于两种推理任务；分任务统计时保留归属，汇总时公开去重问题数，不能把同一道题的多次归属当作独立证据增加置信度。

相同资料允许去重导入，但不能因此删除不同问题。不同上游 ID 却文本相同的题先标记重复组，本版保留原始记录，不静默合并；任何以后改变计分去重策略的决定另记版本。

顺序只用于稳定导出、导入和执行，不再用于“取前 N 题”。本版不抽样，所以不需要抽样随机种子；已有 TruthfulQA 选项顺序的随机种子属于答题协议，继续保留，两者不要混淆。

## 6. notebook 组织与规模分开设计

**选题范围不受当前单库 40 篇资料上限裁剪。** 40 是现有评测适配器与隔离运行配置的约束，不是本方案的题数配额，也不声明为 SN 产品的普遍容量上限。当前代码超出时会报错，本轮不调整该限制。

完整题单与执行分库清单应分别保存。后续执行实现建议采用以下确定性分库设计；它尚未接入当前 runner：

- MMLU 和 BBH 先按选定 task 分组；SQuAD 按选定文章主题分组；DROP、LogiQA 与其他套件保留源记录顺序。
- 同一个原始资料单元对应的全部问题及任务归属一起分配。资料按白名单构造、去重，并按第一次出现的原始顺序排列；不根据参考答案、SN 表现或检索结果进行分库。
- 在每组中按固定资料数量上限连续分库，保存每题到资料及 notebook 分区的映射。共享原文的题留在同一分区，同题的多任务归属也不因分库丢失。
- 先构建所有正资料分区。原三套若沿用干扰段落方案，使用同一冻结来源顺序填充剩余容量，排除当前分区已有资料；没有剩余容量时记录实际干扰数为 0，不挤掉题目所需资料。新七套首版只用题目材料并集。
- 每个分区 × 模式使用独立 runtime/notebook；chunk 与 reasoning 使用完全相同的题单和资料分区。每题新会话，禁用 Memory/偏好/经验注入。
- 每次 Ask 面对所在分区的整个资料库，不逐题把 source scope 限制为 gold 文档。问题提交格式沿用各套适配协议，不把答案写入问题、标题或导入资料。

分库改变了可检索语料范围。报告必须标记“固定分区内的资料检索与问答”，不能据此声称在整套公开数据的统一大库中完成检索。多个分区全部运行后可以覆盖完整题单，但不等于做了全库检索实验。题量、分区数量、文档数量、chunk 数量应分别报告。

这一分库方案与现有“一套一个库”的历史协议不同，需要新的语料组织/运行身份以及明确的分区清单，不能在已有 `sn-public-system-v1` 产物中静默改变范围。后续如提高评测侧容量或采用其他组织方式，重新冻结配置和语料身份，不修改生产项目来绕过当前限制。

## 7. 分数与覆盖率怎样解释

每个 suite/task 分开报告原始范围数量、结构有效数量、独立问题数、任务记录数、产品适用性各状态、计划执行数量、实际输出数量、可评分数量和分数。不把未纳入任务写为零分，不将 N/A 混入语义均分。

执行前，选题清单要对账：范围内原始记录 = 结构有效记录 + 异常记录；有效题单中的产品审核/适用性状态再分别计数。执行后，已有“已知答对 / 全部计划题数”指标继续使用明确的运行分母，同时展示该计划相对于完整选题清单的覆盖率，避免只展示已审核或成功作答子集。

Native 保留完整选题身份，Product 保留适用性与运行分区身份。两条路径有不同的提示词、资料暴露方式和评分约束；不合并总分，不将差值解释为检索造成的损失。

SQuAD/DROP/BoolQ/LogiQA 可以观察配套资料与回答的联合表现；GSM8K/BBH/MMLU/TruthfulQA/HellaSwag 的题面或候选项不是独立事实证据，不默认以 Faithfulness 评价全部任务。引用对象可追溯性单列，逐断言支持关系仍需合适标注或人工判断。

本方案不添加质量阈值。扩大数据量不会自动完成 judge 校准、Agent 轨迹观测、可靠拒答真值或领域覆盖。

## 8. 与已有代码的差异及后续实施顺序

| 部分 | 当前实现 | 按本方案后续需要落实 |
|---|---|---|
| 原五套选择器 | `starter_protocol.select_cases` 固定主题/任务前缀；多数有数量限制，DROP 只取首个合格 section | 用独立选择协议表达本表范围，去掉前缀题额与 DROP 十题资格条件；旧 bundle 继续按旧规则重建 |
| 新增五套选择器 | `select_expansion_cases` 接收本地输入文件的全部行 | 导出阶段按本表 tasks/splits 枚举完整数据，保存上游身份和完整性清单，不能把“文件全读了”当作“上游全覆盖了” |
| 资料库与执行 | 新系统适配仍有 40 篇资料限制，runner 每次使用单个 bundle/notebook | 选题清单不截断；后续实现独立分库清单、完整覆盖对账及匹配的 chunk/reasoning 运行身份 |
| 报告 | 已支持计划/输出/评分分母与单运行配对 | 增加选题总体到各运行分区的映射，明确重复任务归属与尚未运行的分区，避免漏题后显示整体完成 |
| IFEval | 固定版本 DeepEval verifier 直接评分 | 使用原始 instruction/kwargs，保存逐条结果；离线回归检查接入与 SDK 一致，无人工规则审核前置条件 |

实施顺序：先完成选择协议、来源与覆盖清单设计 → 编写保持旧 bundle 兼容的最小改动 → 在用户恢复测试/准备工作后核实真实数据、完善规则审核与分库映射 → 在用户恢复在线任务后按固定执行计划运行 SN，并保留 Native 参照。后续按任务或分区排执行顺序可以控制进度，但不能把未运行的部分从整体范围中删除。

当前不启动上述实施，不修改冻结数据、不重写历史成绩、不提交或推送本轮文档。205 项离线回归是此前代码的验证记录，不证明本方案的新选择器、分库和整体报告已经实现。
