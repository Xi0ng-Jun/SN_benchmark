## 限制与观察

- pi-flash 两个 Agent 各遇 1–2 次 provider 连接错误；工作台消息桥对 error 状态的 Agent 返回 `AGENT_UNAVAILABLE`，续接只能经 Paseo 直接发送，这一段消息不在工作台回执里。
- 同一源码同一模型重跑三题均值差约 0.017（本轮 C0 0.2429，另一 Agent 的同源运行 0.2260）。A 的逐题降幅约 0.03–0.04，与这一波动同量级；单次运行不足以区分改动效果与随机性。
- 比较记录按请求生成（读取不改写已有记录）；scorer／model／config 仍不在 preparation 契约内，配对准入是唯一的同构保证。

## 第三阶段：CLI 动词与待确认请求（事实）

写动词按用户 10-19 的选择实现为“Agent 申请、人确认”（`84539a8`、`14a6545`）。新的分析 Agent（pi-flash）只用 CLI 完成本轮：

| 步骤 | 结果 |
| --- | --- |
| 读动词 | `node list`、`node show A`、`compare A C0`、`case` 均正常；compare 返回已存记录 `99add591…` |
| 申请 | 3 条请求：C0 重跑（噪声基线，理由完整）；建议放弃 A（区分事实与推断）；一条试命令时误提的占位请求（重跑 A，理由仅“x”），Agent 在汇报中自行披露 |
| 人侧处理（`scripts/sn-workbench`，smoke 操作者） | 占位请求附说明驳回；交互确认提示答“n”时请求保持 pending；确认 C0 重跑后服务器以请求 id 为幂等键派发，回执写回请求（executed、确认人、attempt 2） |
| C0 attempt 2 | 3/3 success、admitted；参考仍为 attempt 1。未带 `limit_cny`，因此**没有费用账本**，本次花费未记录（同量级运行约 ¥0.01–0.04） |
| 撤回 | Agent 读到重跑结果后，用新加的 `request withdraw` 撤回“放弃 A”的请求，未另交裁决，结论改为“证据不足、暂不裁决” |

噪声基线（同一源码、同一模型）：

| 题 | C0 attempt 1 | C0 attempt 2 | A |
| --- | --- | --- | --- |
| `6e040e80` | 0.4225（56 词） | 0.3636（15 词，只列两个数据集） | 0.3810（14 词） |
| `aebd1f0d` | 0.1224 | 0.1250 | 0.0791 |
| `cb4086ad` | 0.1837 | 0.1342 | 0.1550 |
| 均值 | 0.2429 | 0.2076 | 0.2050 |

同源重跑均值漂移 −0.035，与 A 的表观差 −0.038 几乎相同；A 相对 C0 attempt 2 只差 −0.003。第一题“答案缩成两个数据集”在未改代码的重跑中同样出现。三次运行在 `cb4086ad` 上的 top-16 检索块各不相同，A 未改检索——运行内检索／查询改写存在独立随机性。**结论：这一三题单次运行的设计分辨不出 A 的效果**；前文“预测 0/3 兑现、守护题下降”是记录事实，不能作为 A 有害的证据。

观察到的产品缺口与处理：Agent 无法撤回误提请求（已加 `request withdraw`）；Agent 只能为本 Task 的候选申请，实现 Agent 只能为自己的候选申请冻结／运行（单测覆盖，本轮未做真实实现 Agent 申请）。
