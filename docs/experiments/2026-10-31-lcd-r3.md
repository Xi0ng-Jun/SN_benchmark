## 1. 问题

在 SN + ALCE-ASQA 上，按方法 v2 连续跑若干轮，产出一条以"已确认改动序号"为横轴、封存集分数为纵轴的曲线。

本轮要回答的是：**采纳规则改成独立样本上的配对净效用之后，父节点能否连续前进，累积提升是否可见。** 不比较优化器，不宣称 SN 的绝对成绩。

次要观测：按 v2 规则，R2d 的候选 A 这类改动（机制已证实、全局提升明显、逐题合同不兑现）能否被采纳。这取代了原计划单独做的候选 A 证伪实验——R3 的第 1 轮自然会重新发现它，结果等价且不额外花钱。

## 2. 起点的选择（已定）

**从 C0 `970b6793` 出发，不从候选 A 出发。**

理由：曲线的第一个点必须是未改动的系统，否则横轴没有基线。而且第 1 轮会重新发现"答案语言不跟随问题语言"这个失败模式，v1 规则下它被判 audit，v2 规则下它应该被采纳——这正是本轮要验证的那件事，放在第 1 轮是免费的。

代价：第 1 轮的提升会明显大于后续轮次，曲线预期是"先陡后平"。这个形状要在报告里预先说明，不能事后解释成方法失效。

- 执行模型、embedding、rerank、答案合成模型：与 R2d 完全一致（答案合成 GLM-5.3）。任何一项变化都会让曲线跨轮不可比。
- SN 起点 commit：`970b6793`（R2d 的 C0）。
- 划分（`split_seed = 20261031`，与 R2d 的 20261025 不同，避免复用）：
  - search / validation：按 paper 60/40，总量与 R2d 同为 150 题。
  - fresh：**数量见 §7.2**，每批题数见 §7.1。从 R2d 未使用的 paper 中不放回抽取。
  - sealed：单独登记，整轮不碰，只在 §6 的终点步骤评一次。

## 4. 协议参数（预注册，运行中不得修改）

```
gate_rule        = lcd-v2
statistic        = paired_raw        # 逐题配对差，原始 str_em，不按 0.5 二值化
cluster_se       = paper             # 按 paper 做族聚类稳健标准误
z_screen         = 0.84              # 筛选：单侧 80%
z_confirm        = 1.65              # 确认：单侧 95%
k_val            = 见 §7.1
k_fresh          = 见 §7.1
n_fresh          = 见 §7.1
b                = 2                 # 每轮实现的假设数
max_clusters     = 4
agent_timeout    = 5400              # R2d 实测分析 49 min、实现 88 min，沿用
infra_retry      = 3
card_approval    = auto
seeded_from      = null
```

**保护指标（必填三项，各带非劣边界）**
| 指标 | 方向 | 非劣边界 | 理由 |
|---|---|---|---|
| 答案语言与问题语言一致率 | 越高越好 | 不得低于父节点减 0.05 | 这是 str_em 的主要刷分方向；A 的收益正是语言修好带来的，后续轮次必须防止反向漂移 |
| 基础设施失败率 | 越低越好 | 不得高于父节点加 0.10 | 沿用 R2d 的 25% 绝对上限，另加相对边界 |
| 每题成本 | 越低越好 | 不得高于父节点的 1.5 倍 | 防止"多列候选答案"式的堆算力刷分 |

任一越界 → `unmeasurable`，不采纳，不消耗该批次的采纳资格但批次仍并入验证池。

**反刷分指标的说明。** str_em 只做字符串匹配，不惩罚多余的错误断言。本轮没有现成的"错误断言率"评分器，所以用"答案语言一致率"加"每题成本"两项做代理。这是一个已知缺口，写在这里以免事后被当成方法保证了没有的东西。

## 5. 判定规则（预注册）

**筛选（验证池）**：`Δ_val − 0.84·SE_val > 0` → 通过；保护指标越界 → unmeasurable；否则不通过。
**确认（新鲜批次）**：
- `Δ_fresh − 1.65·SE_fresh > 0` → **收益成立**，候选成为新父节点。
- `Δ_fresh + 1.65·SE_fresh ≤ 0` → 收益不成立。
- 其余 → 证据不足。**允许再取一个批次做一次合并分析**（每个候选最多一次），仍不足则按不成立处理。
- 保护指标越界优先判 unmeasurable。

**归因标签**（只记录，不参与判定）：支持 / 反驳 / 证据不足，按方法规格 §2.2。被采纳且标签非"支持"的改动标记为"已采纳、未归因"，留给终点的人工复核。

**停机原因**（三类分别记录，只有第一类能解释为"改进空间用尽"）：
1. `no_gain`：连续 2 个诊断周期内，没有候选通过筛选，或通过筛选的候选全部收益不成立。
2. `resources_exhausted`：新鲜批次用尽 / 预算用尽 / 轮数上限。
3. `process_failure`：Agent 超时、基础设施失败率超阈、合同无效连续超限。

## 6. 终点步骤（全部版本冻结之后，只做一次）

1. 固定节点集 = C0 + 全部已确认节点。
2. 对每个节点在封存集上跑 `k_sealed = 2`，同任务配对。

## 7. 待算数值（运行前必须填入，否则不得启动）

### 7.1 由最小可检出效应反推 n_fresh、k_fresh、k_val

方法 v2 要求重跑次数不是固定常数，而是由 MDE 反推。**预注册 MDE = 0.03 str_em**（即单轮改动至少要有 3 个百分点才值得被确认采纳；R2d 候选 A 的验证集 Δ 是 0.118，远在其上）。

需要的输入：C0 在 ALCE-ASQA 上**逐题原始 str_em 的方差分解** —— 题间方差、重跑方差、paper 族内相关 ICC。R2d 的 C0 跑过 2 次 attempt，数据在服务器上，够估一个粗略值。

计算方式（M1 交付的 `paired_delta` 就是这个口径）：
```
SE(Δ) = sd(d_i) / sqrt(n_eff),  d_i = s_cand(i) − s_parent(i),  s(i) 取 k 次均值
n_eff = n / (1 + (m̄ − 1)·ICC)
要求 1.65·SE(Δ) < MDE = 0.03，在功效 0.8 下反推 n_fresh 与 k_fresh
```
**填写：** `n_fresh = ____`，`k_fresh = ____`，`k_val = ____`。

note：R2d 用的 η = 0.0204 是二值化、只用 C0 一侧、k=2 的口径，**不能直接拿来反推**，必须用原始分数重算。

### 7.2 批次预算

每个候选的确认消耗 1 个批次，证据不足时最多再消耗 1 个。按 b=2、目标 5 轮估算，需要 `10 到 20` 个批次。

ALCE-ASQA 共 948 题，R2d 已用 150 题 + 4×50 fresh。剩余题数与 paper 数需核对后确定 `n_fresh × 批次数 + sealed` 是否放得下。**若放不下，优先砍 b 到 1，不砍 n_fresh**（样本量不足会让每一次确认都落到"证据不足"，批次反而消耗得更快）。

**填写：** `批次数 = ____`，`sealed 题数 = ____`，`核对结论：____`。

## 8. 预期（写下以便事后对照）

- 第 1 轮重新发现语言失败模式，候选在验证池与新鲜批次上都应显著为正，归因标签"支持"。若第 1 轮都没有候选被采纳，说明 v2 的实现有问题，应停机排查而不是继续跑。
- 第 2 轮起提升迅速变小，可能出现连续"证据不足"。这是 MDE 与批次大小的直接后果，不是方法失效。
- 曲线形状预期"先陡后平"。能画出 3 个以上已确认节点就达到本轮目的。
- 停机原因预期是 `resources_exhausted`（批次或预算），而不是 `no_gain`。若真的停在 `no_gain`，那是比预期更强的结果，需要先核对筛选阈值是否设得过严。
