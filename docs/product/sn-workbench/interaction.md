# 任务工作面与交互 v0.5

2026-10-12 修订。本稿围绕 [PRD](../../evaluation-improvement-workbench-prd.md) FR-09~14 提供界面起点。配套 [原型](prototype/index.html) 是构造演示，不连接服务；其布局不代表当前可运行应用。开发时继续借鉴 Paseo 的视觉和交互细节，页面、组件及动作位置可随实际使用调整。

## 当前实现的入口分配

2026-10-14 起，“工作”面对齐 Paseo：上方是任务卡（目标、run 卡、SN 改动、待读题），下方是与当前 Agent 的对话，底部一个输入框，输入框内有“材料”附件和 Agent／模型选择（列出本任务 Agent、按服务器允许配置新建、关联已有 ID）。打开任务自动选中最近关联的 Agent 并读取对话；Agent 运行中与发送后短时间内静默轮询。发送默认 interrupt，Enter 发送；送达后自动开始下一条。调查笔记、会话管理面板与发送行为选择已移出工作面；笔记 API 和历史保留。工作面只说明一件事：Agent 只收到用户发送的文字、输入框里列出的附件和它自己用工具读到的内容；每个会话的第一条消息默认带上可移除的角色说明，分析会话还带上“本任务的评测运行”摘要。菜单新建的是分析 Agent；实现 Agent 在“更改”页的假设卡上新建，卡片显示组件、机制、证据、逐题预测、交给实现者的说明，并提供批准／驳回、核对预测、效果与原因结论。附加前先预览原文；run 案例附件含 gold，标为仅供分析。

此前 UI01 针对“内容太杂、设置实际打开资源”的反馈收敛为四个中心工作面：工作、结果、计划、记录（后来加入“更改”）。结果集中结果卡、接入目录与比较；计划保留草稿及固定版本；记录集中候选判断、笔记、人评和事件索引。能力从明确入口进入，普通导航不提交或取消领域操作。具体交付与浏览器证据见[UI01 记录](../../superpowers/plans/2026-10-12-sn-workbench-ui-focus.md)，预览是否更新以该记录为准。

“工作区设置”是独立配置面，读取 bootstrap 已登记的 workspace、操作者、Agent 创建配置、能力声明和评测输入；外观主题可切换，其余服务器配置只读。登记位置不证明实际加载源码已冻结，入口存在不证明远端健康。当前没有配置写入 API，不提供假编辑／保存。后续配置分组及可编辑范围可以随实现演进。

右栏解释当前结果、案例或固定记录。右栏开关恢复上次材料；尚未明确选择结果时，当前会显示任务第一份结果，并在标题标明对象。完整任务记录与结果接入不放在设置或右栏。关闭右栏、切换中心工作面和开关设置只影响展示，保留当前任务／会话／案例选择及页面内草稿；计划 controller 首次打开后保持当前 Task 激活，消息所有权锁不因布局卸载。真正切任务仍执行已有同步失效及迟到数据隔离。未保存输入不保证跨刷新保留，unknown 只能按原请求核对；UI 隐藏不是撤销。

以下流程与动态矩阵包含尚未实现的产品方向，不应据此推断真实 Job 已运行。A／B／C、J01 和隔离 J02 的实际范围各见阶段记录；Job 尚无页面派发入口，真实执行输入及源码／模型／scorer 绑定仍待接通。

## 工作面

当前以左侧 workspace／任务、中间会话与工作、右侧按需阅读材料为起点。栏宽、折叠方式、断点和标签组织随内容与开发反馈调整；原型的 232px／400px 是演示尺寸。材料也可以作为页签或独立面板打开，不要求所有场景固定三栏。

任务头部先帮助用户确认正在做什么、针对哪个 SN 版本、执行到哪里。详细 hash、配置和目录按需展开；未提交改动、评分缺口等会影响当前判断的信息在相关位置显示。Agent 状态、Job 状态和页面连接各自有来源，具体展示位置可以调整。

中间以会话为主要工作入口，计划、进度、成绩和待决事项在需要时出现。专用内容可用卡片、工具结果、紧凑状态行或可展开区块，不固定为四种大卡。长表、证据和 diff 可在材料面板查看，保持对话容易阅读。运行进度可以原位更新，历史保留当时记录；上滚阅读时，新内容不抢走当前位置。

## 专用内容的初步职责

组件名用于沟通职责，开发时可合并、拆分或换成更自然的时间线呈现。

| 内容／拟定组件 | 帮助用户判断什么 | 更新与交互参考 |
| --- | --- | --- |
| TaskHeader | 当前目标、workspace、源码／运行摘要与活动状态 | 打开版本或作业详情，避免把分支名当作实际版本 |
| EvaluationPlanCard | 测哪些题、用什么配置、预算和源码是什么 | 调整选题、保存草稿、提交；已执行的计划保持可追溯 |
| JobProgressCard | 生成／评分各到哪一步，已有多少可读结果 | 随作业更新、查看部分输出、请求取消并显示实际回执 |
| ResultInvestigationCard | 正式成绩、分母与缺口，值得调查的案例 | 打开完整成绩及证据，分别展示规则、模型和人工判断 |
| ChangeValidationCard | 改了什么、怎样验证、前后结果有什么变化 | 打开 diff、拟定验证、读取新结果；已有 dirty 内容不冒充 Agent 改动 |
| DecisionRow | 此刻需要用户决定什么 | 就近选择并保存；得到持久化回执后显示已保存 |
| ContextAttachment | 给 Agent 哪份材料、用于什么 | 添加／打开／移除对象，发送内容与目的地按实际配置说明 |
| MaterialPanel | 当前材料的版本、来源和完整性 | 可展开、关闭和深链；新结果不自动替换正在读的材料 |
| TaskHistory | 当时执行或保存了什么 | 打开当时版本，复制计划时检查当前配置 |

领域内容引用真实计划、作业和结果；Agent 提议可以进入草稿，经领域服务解析并记录后再执行。自由文本本身不证明操作已发生。当前视图可以更新，历史打开原版本；作业完成不等于建议正确或系统已改好。对象引用及 revision 的具体数据表示见[接口草案](api-and-events.md)。

## 核心流程

### 进入任务与拟定计划

1. 打开 workspace 下任务。已有结果可直接读，Agent 不可用不阻止浏览。
2. 用户发消息或点“选题评测”。Agent 提议具体计划，系统以草稿卡呈现。
3. 选题面板保留跨页选择；搜索不清空已选。显示全部已选题数、资料分区、选择规则与 seed。最终冻结具体 case IDs。
4. 草稿保存有持久化回执；提交展示范围、配置、源码与预算。手动模式明确点击；委托模式可在已授权范围提交，显示授权来源和操作回执。
5. 用户主动再次执行才建立新 request key。客户端丢失提交响应先查询旧 request key，不盲目重提。

### 执行与阅读部分结果

生成和评分各自更新，不显示混合总百分比。“查看已有答案”允许运行中阅读，注明 provisional；正式汇总在完整来源校验后发布。官方协议对空回答的有效零分保持数值，生成状态继续表明 no_answer。

发现评分错误时保留已生成答案，补评引用原答卷，新 scores 批次与原批次都可打开。正式配对核对完整声明题单、输入、scorer 和实际分母；附加估计独立呈现，不退回成功题交集，不能从少数已评分题推算正式总分。

### 证据与人评

卡片“查看依据”打开固定案例，先读题目／回答，再按源资料、检索、上下文、引用／真实 span 展开。片段有类型、版本、完整性和节选边界；未采集阶段显示未知，gold 非穷举说明随证据判断出现。

人评紧邻证据：确认／否定／无法判断＋理由与证据引用。同题的不同答卷、人评者与 revision 各有独立输入。服务端以 base revision 检查同一记录流冲突，其他评审者记录并列，不互相覆盖。保存后可继续调查或验证，不自动执行改码。

### 改动、验证与比较

用户与 Agent 围绕具体方向开展修改，沿用已有委托或补充必要范围。可以使用当前 worktree，也可另建；默认方式在开发中结合使用反馈决定。改动可在 Changes 阅读，已有 dirty 内容与本次修改区分，不把所有 diff 都算为 Agent 改动。

当前 runner 的快照入口拒绝 tracked dirty 源码，需要补齐稳定捕获及运行绑定。验证未提交改动仍是产品目标，是否在第一个流程中补齐由实现决定。暂时不可执行的状态解释实际原因并保留材料可读，不将现有入口限制写成永久禁用规则。当前目录、基线与实际被测内容各自有明确来源。

比较先显示完整声明范围的官方成绩及覆盖，随后显示适用的逐题差分、诊断样本和额外样本、代价与退化。配对准入失败允许分别读成绩。效果与原因假设分别填写，保存人评不修改分数，不自动部署。

## 动态行为矩阵

| 情况 | 卡片／面板反馈 | 可以继续做什么 |
| --- | --- | --- |
| Agent 断连，Job 正常运行 | 会话连接错误，Job 保留最新查询和时间 | 手动查询、看成绩或取消 Job |
| 页面离线 | 旧快照＋更新时间，写动作不可提交 | 继续读已缓存内容，恢复连接 |
| API 重启 | 读取固定记录；实际 Job 由 worker 查询 | 不重新执行既有提交 |
| worker／整机中断 | reconciling，核对后 interrupted 或真实终态 | 查看已保存材料，明确新 attempt |
| 取消与完成竞争 | 先完成则提示已结束，不改 completed | 打开完整结果 |
| 中断 Agent | 独立请求与回执，Job 卡不变 | 继续手动或换 Agent，必要时单独取消 Job |
| 分析预算耗尽 | 已完成建议＋未分析范围，partial | 读已有结果，另建明确预算的分析 |
| 没有足够依据／零建议 | 说明检查范围、未决或无可支持建议 | 打开案例／补观测，不制造建议 |
| 分数与人评不一致 | 并列官方值和判断 | 记录评分异常候选，官方值不被覆盖 |
| 源码／运行身份未知 | 头部和验证卡说明未知 | 浏览、调查，暂停有确定版本归因的执行 |
| 同 checkout 存在未核对的并发修改 | 显示当前改动及可能影响 | 阅读 diff，核对来源，选择适合的协调或执行快照 |
| 服务端修订冲突 | 保留本地理由，对照基线与新修订 | 人工合并后提交新 revision |
| 右侧正在读案例，收到新结果 | 当前材料不自动替换，显示更新入口 | 用户主动打开新结果 |
| 关闭右侧／浏览器 | 仅改变布局或连接 | Job 继续由 worker 管理 |

取消／重新生成／委托改码通过明确动作展示范围。普通导航、保存草稿和人评无需重复确认。工具、费用、输入目的地发生超范围变化才另作决定。

## 原型与验收覆盖

原型用于讨论导航、会话与专用内容的组合、选题附件、生成／评分独立、取消请求与确认、连接与 Job 分开、成绩与证据、人评、Changes、验证及固定历史。自选范围与固定演示范围各自独立；演示推进控件用虚线明确标注。

后续浏览器及用户评审重点：任务与作业能否区分；下一步是否容易找到；右侧宽度能否读长证据；完整成绩是否被摘要遮挡；暂停 Agent 与取消 Job 是否清楚。当前未执行可用性脚本或测试，不能用代码数量和可点击按钮数声明体验通过。
