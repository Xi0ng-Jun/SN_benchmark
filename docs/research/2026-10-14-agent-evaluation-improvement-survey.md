# SN 评测改进闭环中的 Agent：接口、编排、验证与自动优化研究

研究日期：2026-10-14。代码基线：`a543e49e65b9d45d20629805da3a800c4c01cf2b`。本文是研究判断和待验证路线，不是已批准的实现规格。

## 先给结论

**当前方案值得加强，但没有证据支持先换框架、换成 MCP，或增加更多角色。最优先的改动应是让分析和交接产生可检查的证据产物，并在服务端核验关键前置条件。** CLI 可以继续作为稳定入口；模型在阶段内部自由调查；预算、输入身份、批准、证据完整性和终态由程序管理。这个组合与已有 runner 和工作台结构相容。

优先借鉴五个机制：

1. **为 Agent 设计“动作＋反馈”，而非只列命令。** SWE-agent 的接口消融支持简洁检索结果、局部上下文、执行后反馈和编辑检查；CodeAct 支持在适合的任务中用代码组合多个动作。但两者都不证明某种序列化格式普遍更可靠。[SWE-agent §3、§5.1](https://arxiv.org/html/2405.15793v3)、[CodeAct §2](https://arxiv.org/html/2402.01030v4)。
2. **用可执行的证据与阶段检查补强 brief。** Agentless 的复现测试和回归测试筛选比单纯多数投票更有依据；迁移到本项目，应检查证据引用、比较身份、未知项和交接工件，而不是要求模型机械执行一长串命令。[Agentless §3、§5.2.3](https://arxiv.org/html/2407.01489v2)。
3. **把执行反馈保留成优化材料，同时隔离最终评估。** GEPA 的轨迹反思和候选谱系、AFlow 的成功与失败修改记录，适合改造“读失败→提假设”的过程；其优化成绩并不等于正确找到了原因。[GEPA §3、附录 E/H](https://arxiv.org/html/2507.19457v2)、[AFlow §4](https://arxiv.org/html/2410.10762v3)。
4. **验证者的价值来自独立证据和检查能力。** 新会话、另一个角色名或多数同意，都不能保证独立验证；需要测试、反例、原始工件和受控的信息边界。MAST 提供了交接失败、错误假设、遗漏验证和提前停止的实证分类。[MAST §3–5、附录 H](https://arxiv.org/html/2503.13657v3)。
5. **审计改进过程本身。** 自动科研系统的研究表明，最终报告会隐藏实验选择和评价错误；应保存未采纳候选、全体尝试、数据暴露和运行失败，而非仅保存最终高分答案。[AI Scientist Pitfalls §4–7](https://arxiv.org/html/2509.08713v1)。

**本项目已经有的重要优点应保留。** 假设卡有逐题预测和证伪条件，人批准后才能创建实现者；源码捕获、独立 runtime、官方 scorer 和配对准入已有实现；效果与原因分别结论。真正薄弱的是“证据是否足够、说明是否忠实、分析是否漏检”尚主要依靠模型和人，以及 gold 边界没有强制文件隔离。三题实验中两升一降、目标题预测失败、候选不采纳，证明了一次可追溯的小闭环，并不证明这套 Agent 方法有效。[项目当前状态](../../CURRENT_STATE.md)、[三题实验](../experiments/2026-10-14-r1-ordering-loop.md)。

建议顺序：**路线 A 的离线诊断对照 → 必要时路线 B 的有限编排 → 有足够独立样本后再做路线 C 的自动优化。** 本轮没有执行这些实验。

## 4. 八篇细读：机制、实验与不可外推之处

### P1. CodeAct：代码是可组合动作空间，不是万能工具协议

**[论文事实]** 在持久 Python 解释器中生成动作，变量传递中间结果，循环/条件组合工具，执行结果和异常反馈用于下一轮修正。§2 固定已有模型比较代码、文本、JSON；§3 另用 CodeActInstruct 微调，后者是训练收益，不能算作换接口的收益。

表3的 M³ToolEval 有 82 个人工任务：GPT-4-1106-preview 的成功率 CodeAct 74.4%、JSON 52.4%，平均轮数 5.5 与 7.6。反例在表2：同模型的 API-Bank 原子调用正确率，JSON 82.7%、CodeAct 76.7%。这些是特定模型与动作预算下的作者结果；一段代码能做多次调用，轮数不是计算量或副作用次数。

**[迁移推断]** `sn-eval` 已允许模型用 shell/Python 聚合 JSON。值得增加的是批量读证据、稳定对象引用和紧凑反馈；目前不必引入任意代码执行服务。若采用代码组合，仍应逐个记录领域动作、限制输出和副作用，不能把一段脚本成功当作所有步骤成功。

原文：[v4 正文](https://arxiv.org/html/2402.01030v4)。官方材料：[code-act](https://github.com/xingyaoww/code-act)，已核实 README 中模型、数据、评测及执行环境入口；未运行或验证模型复现。

### P2. SWE-agent：最直接的接口设计证据

**[论文事实]** ACI 同时设计命令、返回内容与历史管理：摘要式搜索、带位置的局部文件视图、编辑后回显、lint 失败反馈/拒绝非法编辑，以及压缩旧 observation。仍建立在 shell 上，不是禁止终端。

表1在 SWE-bench Lite、GPT-4 Turbo 条件下，SWE-agent 18.00%，带示例 shell-only 11.00%，无示例 shell-only 7.33%。表3去掉编辑 lint 从18.0降到15.0；整文件视图为12.7，100行视图为18.0。§4设每题4美元上限。这支持特定反馈/上下文设计有效，不是“结构化 tool 天生胜 CLI”；论文成本口径也不应当作今天的预算报价。

**[迁移推断]** 对 `case` 的返回，优先考虑状态、证据来源、截断信息、缺失原因和按需展开；对假设卡提交返回逐项问题及可定位引用。不要用盲目截断节省 token，以免把缺证据变成模型编造解释。收益需在我们的分析任务和 provider 上重测。

原文：[v3 正文](https://arxiv.org/html/2405.15793v3)。官方材料：[SWE-agent](https://github.com/SWE-agent/SWE-agent)，核实代码、配置/文档与运行入口；当前仓库版本不等于论文版本，未部署。

### P3. Agentless：先有可运行的反例，再谈自主修复

**[论文事实]** 三阶段为分层定位、补丁生成、验证选择；从文件树到符号骨架再到编辑位置。生成复现测试先在原代码上执行；结合回归测试筛选补丁，最后规范化多数投票。§4默认每 issue 40 个补丁、40 个复现测试候选，不是一次便宜调用。

§5.2.3表4，在同一 SWE-bench Lite 300题、GPT-4o 设置中：仅多数投票修复77题，加入回归测试81题，再加复现测试96题。局限在§3.3和图7：生成测试可能错误；无人通过时有回退策略；测试在旧版本失败也不保证测试正确。其部分回归测试筛选依赖模型判断，不能直接照搬为本项目可让模型删守护题。

**[迁移推断]** 要求实现交付合成反例、旧版本失败/新版本通过的回执及守护测试；验证者另写性质检查或独立参考检查。固定的“证据整理→候选假设→检查”流水线应作为自主分析的低复杂度对照，不必把实现者完全改成 Agentless。

原文：[v2](https://arxiv.org/html/2407.01489v2)、[作者 FSE 正式 PDF](https://lingming.cs.illinois.edu/publications/fse2025.pdf)。官方材料：[Agentless](https://github.com/OpenAutoCoder/Agentless)，核实阶段脚本与评测说明；未执行 SWE-bench，正文数字固定取 v2，不混用后来榜单。

### P4. GEPA：把失败轨迹变成候选，而非直接变成“经验真理”

**[论文事实]** 固定模型权重，反思模块输入/输出、执行轨迹及评价反馈，修改 prompt；先小批次检验，再在选择集评价，保存父子关系。候选选择保留在不同实例上有优势的方案，避免只沿当前均分冠军搜索；还研究互补候选合并。

v2 表3固定演化框架和 Qwen3-8B，HotpotQA 条件下 Pareto 选择62.33，贪心58.33，beam57.33；附录 E.1 为150训练、300验证、300测试。表1也有 AIME 上 GRPO 胜 GEPA 的反例。rollout 数不是总美元/算力：反思调用、验证选择、最终 prompt 长度必须另计（附录 E/I/N）。论文优化结果支持搜索策略，不提供模块因果归因保证。

**[迁移推断]** 可在分析开发集上优化 brief 或某一诊断步骤，保存“改了什么、依据什么、在哪些题上失败”。不把 gold 反馈直接放入 SN 生成提示；也不因某候选有一题优势就批准部署。Pareto 搜索适合保留探索分支，最终选择仍遵守预先约定的指标与风险约束。

原文：[v2](https://arxiv.org/html/2507.19457v2)、[版本与发表声明](https://arxiv.org/abs/2507.19457)。浏览工具因页面过大失败后，实际经 HTTPS 下载并阅读正文和附录。官方材料：[gepa](https://github.com/gepa-ai/gepa)，已核实实现、adapter/examples 入口；未复现论文配置，仓库当前能力不作为论文已证明能力。

### P5. AFlow：自动搜索流程与运行时编排是两回事

**[论文事实]** 每个搜索树节点是一份完整可执行 workflow；LLM 修改 prompt/连接/代码，执行评价后回传分数与修改经验。搜索可从初始模板重新探索；存在最大轮数及连续无改善停止条件。§4还保存失败修改，不只保留成功路径。

§5.1使用六任务，Claude-3.5-Sonnet 作优化器、GPT-4o-mini 等作执行器。数据按20%验证、80%测试切分；先在验证部分选择高方差题，每候选验证重复5次，主表测试重复3次；默认搜索20轮。不能把这里的 HotpotQA 分数当本项目全量官方成绩。频繁选择验证集、模板/算子设计和搜索成本都是前提；自动生成工作流不等于自动发现正确的实验设计。

**[迁移推断]** 先固定少量允许动作与评价函数，再探索检查顺序或失败后的分支。不要让搜索器修改批准条件、scorer、分母或最终保留集。工作流优化器不应成为运行状态的第二个真相源。

原文：[v3](https://arxiv.org/html/2410.10762v3)。官方材料：[AFlow](https://github.com/FoundationAgents/AFlow)，已核实算子、benchmark、搜索与基线入口；README 提醒从 MetaGPT 迁移的算子可能有 bug，因此只能说材料可得，不能宣称开箱复现。

### P6. Agent Laboratory：阶段产物有用，自评不够

**[论文事实]** 文献、计划、数据准备、实验、解释、报告分阶段交付，可接受人类反馈；mle-solver 维护候选程序池，执行、修复、打分、反思再选择。正文的研究计划一致性评分使用 LLM；MLE-Bench 子实验另用 dev 指标，并非同一验证机制。

v2 §4.1/4.1.1：五主题×三模型产生15篇报告，10名博士志愿者各评3篇；图6自动评审均值6.1/10，人评3.8/10。§4.4只选10个低复杂度文本/表格挑战，且对其他方法的无效提交从均分排除；不能据此给一般研发 Agent 排名。§5明确报告幻觉、上下文超限、循环和宿主执行等局限。

**[迁移推断]** 可复用阶段产物和人工 checkpoint；不采用“另一 Agent 觉得科学性不错”作为验收。我们的官方 scorer、固定分母和预注册预测比自评报告分更适合当前目的。运行完成、实验设计有效、报告忠实必须分别检查。

原文：[v2](https://arxiv.org/html/2501.04227v2)。官方材料：[AgentLaboratory](https://github.com/SamuelSchmidgall/AgentLaboratory)，核实工作流、solver 文件与使用说明；没有运行，也未核实论文所有人评/计算条件能完整重建。

### P7. MAST：角色增加之前，先知道交接哪里失败

**[论文事实]** v3将失败分为系统设计、Agent 间不一致、任务验证三类14种；来源包括专家近读和 LLM 扩展标注。§3说明1642条轨迹并非全部多人手标；专家一致性与自动标注可靠性是两种证据。

附录 H 表5提供干预而非只有分类：ChatDev 在32个 ProgramDev-v0 任务上，基线25.0%，修改 prompt 34.4%，新拓扑40.6%。新拓扑增加循环复核和停止控制。反例是 AG2/GPT-4 的新拓扑改善不显著，作者报告 p=0.4。不同任务混合的故障分布不能当线上生产失败率，也不能证明增加验证角色的等成本收益。

**[迁移推断]** 给本项目分析轨迹标记“错误假设传递、信息缺失、未核验、错误核验、提前终止、重复动作”，再决定是否加验证者。归类可以辅助找问题；要声称根因，仍需干预。先校准本项目标注规则，再考虑 LLM 批量标注。

原文：[v3](https://arxiv.org/html/2503.13657v3)、[NeurIPS 正式条目](https://proceedings.neurips.cc/paper_files/paper/2025/hash/b1041e52d3be19f0a9bc491657488e4a-Abstract-Datasets_and_Benchmarks_Track.html)。官方材料：[MAST](https://github.com/multi-agent-systems-failure-taxonomy/MAST)，核实分类、轨迹、人工一致性材料与 judge notebook；未运行。早期 v1/v2 样本量不同，本文定量描述以 v3 为准。

### P8. AI Scientist Pitfalls：报告看起来完整仍可能评价错了

**[论文事实]** 用合成 SPR 任务控制数据难度、名称和呈现顺序，检查 benchmark 选择、泄漏、指标使用、事后挑选。§5没有观察到两系统直接偷看测试数据的证据，却发现未披露的子采样/造数据及用测试表现筛实验的风险；不能把潜在风险全部写成已发生。

§6.2每类构造200个正负平衡审计样本，部分稀少错误人工注入；独立 Gemini 分类器比较仅报告与报告＋日志＋代码。表11总体准确率51.4%→74.0%，但后者假阳性率仍30.0%。这是限定的审计任务，不是自然事故率或可靠自动审批能力；§7也限制了两系统和合成任务的外推。

**[迁移推断]** 验证者应读取冻结计划、所有 attempt 与工件，而非只读实现者总结。为候选选择记录开发/验证/最终评估数据的可见范围；最终测试分数即使没有逐题 gold，只要反复据此选择，也会成为优化反馈。

原文：[2025 v1](https://arxiv.org/html/2509.08713v1)。官方材料：[AIScientistPitfalls](https://github.com/niharshah/AIScientistPitfalls)，核实合成任务、两系统实验目录、检测数据/代码；未下载完整数据或复现实验。OpenReview 入口受浏览验证阻挡，改读作者 arXiv 全文；未据搜索摘要认定后续出版状态。

## 6. 回答五个研究问题，并映射到当前差距

### 6.1 工具定义、发现、选择和调用

**[迁移推断]** 当前 CLI 的方向合理，问题在其任务契约和反馈是否适合模型。可在 `agent_tools.py` 共享命令描述中补充输入类型、作用域、输出 schema 版本、副作用类别、错误类别、截断/缺失标记、下一步可选操作。CLI、Python API 或未来结构化 tool wrapper 都调用同一领域逻辑，避免两套校验。

建议区分如下收益及验证方式：

| 机制 | 潜在收益 | 不能替代的东西 |
|---|---|---|
| CLI＋明确帮助/稳定 JSON | 易手工复查、可组合、跨 provider | 参数合法性不等于任务正确；shell 报错不是领域错误分类 |
| 结构化 action schema | 更早发现缺字段/类型错，限制可见动作 | 不认证身份、不确认批准、不证明动作选对 |
| 代码动作/批量读 | 少往返、复用中间值、批量分析 | 每个底层动作的成本/失败/授权审计 |
| ACI 的 observation 设计 | 降低上下文噪声，让实际结果更清楚 | 被摘要丢失的证据不能用模型补造 |
| 工具检索 | 大工具集缩小候选范围 | 检索漏召会使正确工具不可见；小集合可能得不偿失 |
| 工具使用训练 | 学习选择、参数与恢复模式 | 训练分布外工具的可靠性与运行时边界 |

将 `schema_version/status/data/evidence_refs/coverage/error` 视为候选语义字段，不先固定永久 schema。`coverage` 需要区分“完整、部分、未观测、不适用”；错误应包含可行动原因，但不能泄漏私有配置。成功返回 JSON 与执行所有必要分析检查是两件事。MCP 只解决部分工具暴露和协议问题，本次未找到“换为 MCP 本身提高本项目正确性”的因果证据。

### 6.2 自由规划与显式流程

**[迁移推断]** 采用“粗粒度阶段＋阶段内自由调查”最贴近现有代码。阶段之间检查可观察产物，而不规定必须先后调用哪些命令；模型可以直接发现已足够的证据，也可以停在“证据不足”。

候选阶段为：证据观察 → 假设草稿 → 人批准 → 实现产物 → 确定性验证与配对实验 → 效果/原因结论。**这是对现有状态的分析视图，不建议另造重复状态表。** `hypotheses.py` 管理卡片状态；消息/创建意图各自管理外部副作用；`notebook_job.py` 及执行层管理运行状态。

| 事件 | 建议决策依据 | 恢复/停止语义 |
|---|---|---|
| 工具参数或格式错误 | 确定性校验错误 | 可在有限次数内纠正，不重做已完成步骤 |
| 只读数据暂不可用 | 原因、来源身份、刷新结果 | 有限重查；持续不可用则“证据不足” |
| 付费/外部副作用结果未知 | 已保存 intent、原请求 key 与真实回执 | 保持 unknown；只读协调，不由 Agent 猜测失败并重发 |
| 卡片证据发生变化 | 卡片版本、source ref、输入哈希 | 已批准内容失效时重新进入相应检查，不沿用过期批准 |
| 同一错误反复发生 | 相同错误签名且没有新证据 | 停止/交给人；不继续堆提示和工具调用 |
| 取消或超时后迟到产物 | attempt 身份和终态 | 保留为迟到证据，不覆盖已定终态或自动启动后续阶段 |
| 达到分析预算/无进展 | 外部 Agent token/时间、工具/模型调用账本 | 交付已知/未知与工件；不把预算耗尽包装成完成 |

checkpoint 应保存已确认事实、未完成动作、输入版本和未知副作用，恢复时先与事实源核对。聊天摘要可以帮助模型理解，但不能作为唯一状态数据库。状态机能阻止未经批准的转移，不能靠“处于 Verify 状态”证明验证完成。[StateFlow §3](https://arxiv.org/html/2403.11322v5)。

### 6.3 错因、假设、改动与对照实验

**[迁移推断]** 在现有假设卡上优先补足如下可核验关系，而不是加更多长文本：

- **观察**：具体工件/字段、实际值、来源版本、是否完整；与该观察冲突的证据。
- **假设**：组件机制、替代解释、当前支持程度；“不知道”是合法结果。
- **干预**：只改变哪个因素，预计哪个中间量和终点量变化，什么结果否定机制。
- **验证计划**：合成反例、受益和受害输入、配对条件、开发/保留样本、预算及停止条件。
- **结果**：所有 attempt、未定项、负结果、偏离计划的地方；效果与原因仍分别决定。

例如“调整最终证据呈现顺序改善枚举回答”：端到端重跑能检验整体效果；要归因于呈现顺序，还需固定查询改写、最终证据文本多重集合、截断、引用映射和生成参数，单独重放呈现/生成边界。随后再用完整 fresh runtime 测集成效果。**固定中间态的诊断结果不是正式端到端成绩**，也不能把 gold 注入的 oracle 诊断混入无 gold 答卷。当前三题报告已经显示为什么这种区别必要。[三题混杂说明](../experiments/2026-10-14-r1-ordering-loop.md)。

阶段重放若将来实现，缓存/快照键至少含输入内容、生产者源码、相关配置、提示与模型身份；未知的远端模型变化必须披露，不能以文件 hash 代替。旧快照只在声明相同边界条件的诊断中复用，不能变成默认生成缓存。

失败记忆建议为“触发条件—证据—曾尝试干预—结果—反证—适用版本”，保留 `refuted/undecided`。只有同类问题才检索相关记忆；代码或协议变化后重验。仅由模型反思得出的规则不能自动升级为永久约束，避免把一次错误归因固化。[Reflexion §3/5](https://arxiv.org/html/2303.11366v4)、[GEPA §3](https://arxiv.org/html/2507.19457v2)。

### 6.4 多角色交接与真正隔离

**[迁移推断]** 保留分析者与实现者分工的合理理由是减少 gold 直接塑形代码，而非声称两个模型比一个聪明。若增加验证角色，交接应是以下工件，而非“请审查上面的结论”：

| 接收者 | 应收到的可检查产物 | 不应被默认授予的能力 |
|---|---|---|
| 分析者 | 开发案例证据、运行状态、协议、只读源码；自己结论与来源逐项绑定 | 修改正式 scorer、删题或启动付费重试 |
| 实现者 | 冻结批准说明、机制约束、合成反例要求、受害条件、起点与允许改动范围 | gold、题目明细、最终保留集，或绕过批准改实验条件 |
| 代码验证者 | 批准规格、基线/候选源码身份、diff、实际测试回执、独立生成的边界测试 | 自行调整预期结果以接受补丁；默认看 gold 也无必要 |
| 评测验证者/人 | 冻结计划、完整分母、官方 scorer 产物、全部 attempt、逐题预测与证据 | 把“多数 Agent 同意”写成因果证据 |

独立性至少有三层：**上下文独立**（先自行核对，避免被作者结论锚定）、**方法独立**（性质测试/参考实现/原始工件）、**能力与数据独立**（不同文件挂载、身份、网络与运行权限）。换模型可作为额外变量，但不能代替这三层。

如果将来要求强制“实现者无法读取 gold”，需在 runtime/OS 边界只挂载批准材料和 SN checkout，隔离评测 state、共享 home/缓存/日志/宿主 socket，并让工具服务按服务端会话身份授权；同时检查网络或其他通道能否重获公开题集。单独 worktree、CLI role 或模型自愿不读均不足。即使实现强隔离，公开 benchmark 的预训练污染仍不能因此排除。

多 Agent 更值得尝试的条件：任务能拆成独立证据调查/独立测试、共享写状态少、每份交接可以客观检查，且预算允许。顺序依赖强、相同上下文反复转述、全部角色依赖同一错误假设时，应先与单 Agent＋结构化检查和单 Agent＋额外自查预算比较。现有研究支持这种条件性判断，没有给本项目角色数量的通用最优解。[MAST 附录 H](https://arxiv.org/html/2503.13657v3)、[等预算研究 §4–6](https://arxiv.org/html/2604.02460v1)。

### 6.5 评价 Agent 机制，而不是只评价 SN 分数

**[迁移推断]** 应建立独立的过程评价集：输入是冻结失败证据包/合成故障，输出是诊断、假设卡、检查回执或恢复决策。它可以使用现有五套的开发材料和脱敏/合成运行工件，不引入新的 SN benchmark。

| 维度 | 可测定义 | 防止误读 |
|---|---|---|
| 任务成功 | 在全部分配任务上完成有效产物；或正确停止于证据不足 | 不把合法 JSON、进程 exit 0、会话 idle 当完成 |
| 证据忠实度 | 引用可解析比例；原始材料实际支持的断言比例 | 人工盲审区分事实/推断；存在引用不等于蕴含 |
| 漏检与误报 | 已知故障的检出/漏检；正常样本的错误阻止率 | 要有无故障负样本、未知原因样本，不能只放显眼坏例 |
| 假设质量 | 可证伪性、替代解释、预测是否明确；干预后是否兑现 | “可写假设”与“找对原因”分开；小样本不拟合置信度 |
| 恢复可靠性 | 注入故障后正确恢复或安全终止；重复副作用/终态覆盖次数 | unknown 保留不算恢复失败的同义词；不能奖励盲重试 |
| 可重复性 | 同输入多次成功率、方差、全部重复成功比例 | pass@k 与 pass^k 分开；不得挑最好的一次 |
| 成本 | 分析/实现/验证/SN/scorer 的 token、调用、美元或人民币估算、时延、人工分钟 | 搜索成本与部署后单次成本分开；失败/取消也计入 |
| 泛化 | 未参与方案选择的案例组/故障家族、跨任务/模型的效果 | 测试集反复查看即会变成选择集 |
| 可复现 | 代码/提示/数据/工具/模型标识、种子、全部工件及重算结果 | API 模型漂移、不可见训练数据、未观测调用保留未知 |

正式 SN 指标依旧分 benchmark 报告，不制造跨五套总分。Agent 过程分数与 SN 答案/证据分数并列呈现；过程改进的最终价值是以更少成本产生可复核、能在保留集上受检验的候选，不是“分析写得像专家”。

## 7. 三条路线：建议位置、成本与最小证伪实验

下列均为下一阶段候选。涉及真实 Agent/SN 调用的实验需要后续具体预算授权；本轮只有研究，没有执行。样本规模是试验起点，不是永久门槛。

### 路线 A：最小增量——保留 CLI，增加证据契约与提交前检查

**建议位置与收益。** 在 `agent_tools.py` 增加可发现的参数/结果说明和稳定错误分类；`context.py` 保持可回溯快照及缺失标志；`hypotheses.py` 在形状检查之外核对引用属于正确任务/run、预测对象可解析、比较条件与必要未知项；`briefs.py` 解释何时停在证据不足。先不增加新 Agent，不改 runner。预期减少找错运行、误解 missing、漏替代解释、提交悬空引用等低层错误。

**检查边界。** 确定性检查只负责能机械核验的事实；不得强制“必须判定某个根因”。语义断言支持度仍需人或独立审查。卡片可以草拟尚待查证的假设，但进入批准前应显式暴露缺口。保留原始证据，不让摘要工具自动写诊断。

**复杂度与失败边界。** 相对低至中：主要是既有服务的输入/输出和局部 schema 演进，成本以维护与少量额外上下文为主。风险是检查表只提高格式合规、增加无用读取，或把真正的新型问题误判为不合规。语义错误不会因字段齐全消失。

**最小证伪实验 A。**

| 项目 | 设计 |
|---|---|
| 最先检验的假设 | 本项目失败有足够比例来自证据取用/提交遗漏，而非模型不具备诊断能力。先人工盲审已有脱敏分析产物；若主要都是深层机制误判，则缩小 A 的预期收益。 |
| 样本 | 开发约12个证据包用于设计；另封存约24–40个包用于比较，按论文/会议/故障家族分组。含服务失败、证据缺失、低词面分但语义正确、混杂、正常无故障例；合成注入放副本中并单独标记。现有三题只作开发例。 |
| 对照 | A0当前 brief＋CLI；A1只改善接口/反馈；A2在 A1 上加可执行提交检查。若预算允许增加“只加同样文字清单”一组，区分提醒与程序约束。 |
| 控制 | 同模型快照、相同可见证据/工具业务能力、任务顺序随机化、相同总 token/时间上限、相同人类反馈；每组新会话，保留全部失败与重复。 |
| 测量 | 忠实断言、悬空引用、漏检/误报、正确的未知判断、有效卡片率、token/时延、人工修订时间；盲审者不知道组别。 |
| 否定结果 | 仅格式更整齐而忠实度/漏检无改善，或改进只在开发包出现，或额外成本/正常任务误阻止抵消收益：不继续扩展 gate。若 A1 已达成同样收益，放弃 A2 的额外约束。 |

第一步可以只做无模型的工件核对和历史人工审计，先验证是否确有目标错误；未来 Agent 对照另计预算。合成故障证明检错能力，不能替代真实诊断泛化。

### 路线 B：较强编排——有限阶段、持久交接、受控验证能力

**建议位置与收益。** 让既有 `hypotheses.py` 状态消费明确的分析/实现/验证工件；复用 `agent_messages.py`、`agent_creations.py` 的 intent 与 unknown 语义；`hypothesis_worktrees.py` 管理目录身份；bridge 仍只负责外部通信。若需要真隔离，落在 provider/runtime 启动和操作系统权限层，不能只改 `briefs.py`。验证角色仅在其有独立检查能力的阶段启动。

**复杂度与失败边界。** 中至高：增加状态转移前置条件、恢复协议、版本绑定和运行隔离维护；验证者增加推理与等待成本。状态太细会固化错误流程；受控停止可能降低“看似完成率”，但应减少重复副作用和伪完成。仍不能保证模型的科学判断正确。

**最小证伪实验 B，先离线故障注入再考察角色。**

| 项目 | 设计 |
|---|---|
| 最先检验的假设 | 当前缺的是跨阶段完成语义，而不只是界面显示或 brief。先画出真实 artifact/intent 转移，寻找可复现缺口；已有正确处理的 unknown 不重复开发。 |
| 对照 | B0当前外壳；B1增加工件前置条件但使用同一分析者；B2在 B1 基础上增加独立验证者。给 B1 等额外预算用于自查，使 B2 不能只靠多花 token 获胜。 |
| 故障集与保留样本 | 在无模型 fixture 中注入发送后断连、重复请求、取消后迟到、实现目录变化、过期证据、测试回执缺失。调试集和保留集用不同发生时机/顺序组合；另留正常路径检查误阻止。 |
| 控制 | 同领域动作、相同输入身份和运行模拟器；只改变编排/验证方案。Agent 阶段仍用冻结证据，隔离和角色数作为两个因素分别实验。 |
| 测量 | 重复副作用、终态覆盖、过期产物进入后续阶段、正确恢复/安全停机、人工接管时间；再测盲审漏检、成本与时延。 |
| 否定结果 | B1不能减少目标生命周期错误却增加死锁/误阻止，则不扩大状态机；B2相较等预算 B1不降低语义漏检，或错误高度一致，则不保留常驻第三角色。 |

能力隔离另做可观察的合成 canary 测试：实现者能读批准包，不能经通用文件、终端、环境或服务通道取得被保留的合成标记。canary 成功只能验证所测访问路径，不能宣称公开 benchmark 预训练污染已消除。不要为测试读取真实密钥或把真实 gold 放入攻击提示。

### 路线 C：研究探索——在有限搜索空间里优化提示或工作流

**建议位置与收益。** 将 `briefs.py` 的分析指令或一段诊断流程作为可版本化候选，复用 `agent_tools.py/context.py` 的稳定动作与反馈；由 `hypotheses.py` 的工件关系连接候选、尝试和结论。先研究一个变量，例如“怎样从证据形成可证伪假设”；成熟后才扩展到有限 workflow 算子。GEPA/MIPRO 是 prompt 候选搜索，AFlow 是流程搜索，不能同时引入后把收益归给某一个。

**复杂度与失败边界。** 高：需要足够多且高质量的诊断标签、昂贵的多候选评价、搜索账本和真正不参与选择的保留集。主要风险为 reward hacking、选择集过拟合、候选提示夹带题目特例、优化成本大于长期收益。当前一次三题实验不足以启动可靠的自动搜索。

**最小证伪实验 C。**

| 项目 | 设计 |
|---|---|
| 最先检验的假设 | 可用反馈能区分好坏诊断。先用有明确因果注入与真实人工裁决的开发包校准评分；若评分只奖励文风或证据数量，停止自动优化。 |
| 对照 | C0人工修订/随机搜索；C1基于轨迹文字反馈的有限 prompt 搜索；必要时 C2再开放流程连接。统一 proposer、执行模型、候选预算；另做去掉文字反馈/去掉候选多样性消融，避免把所有收益归给反思。 |
| 数据划分 | 训练集可看细节与标注；选择集只按预定协议用于选候选；最终保留集在候选冻结后评价。按来源/问题族分组，禁止把同论文不同题当独立训练和测试。未来可用另一个保留 suite 做迁移检查，但不合分。 |
| 搜索约束 | 不许更改 scorer、分母、批准与访问控制；只在开发轨道使用 gold 反馈；所有失败候选、成本及淘汰原因入账。保留集结果不回流本轮搜索。 |
| 测量 | 未见样本忠实度/漏检、假设可检验性、经后续批准实验的预测兑现、总体成本收益、开发与保留差距；记录每种搜索实际训练/选择调用与反思成本。 |
| 否定结果 | 相对等预算简单基线无保留集提升，增益只来自具体题目记忆，换模型/故障家族即消失，或预算内不能回收搜索成本：停止自动搜索，保留手工机制。 |

搜索器发现“更高分的候选”后仍交由人审核实验，不自动执行 SN 或采纳改动。论文中“优化成功”与本项目“科学归因成立”具有不同验收条件。

## 8. 避免 benchmark/gold 过拟合的具体实验规则

以下是研究建议，不擅自改变既有正式协议或阈值。

1. **登记暴露，不仅登记切分。** 每个案例组记录谁看过问题、gold、分数、逐题反馈、哪一轮选择过候选。分析者读过的 gold 是开发监督；卡片、记忆和提示由其产生也可能携带信息。文本泄漏扫描 clean 不代表没有过拟合。
2. **按依赖分组留出。** QASPER 按论文、QMSum 按会议；HotpotQA/MultiHop-RAG/ALCE 按问题家族和共享来源关系设计可行切分，披露共享语料。不能机械要求整套共享语料完全断开，也不能把高度相关题当独立样本。既有路线图提到的留出题需核查实际暴露历史，不能仅靠名字认定仍盲。
3. **选择验证集和最终测试集分开。** 少量反复展示的验证分也会影响选择。最终保留集一旦用于决定下一次改法，就应重新标为开发/选择材料；不要通过重命名恢复其独立性。公开训练污染只能披露并用新组合/合成反例辅助检验，不能宣称被完全排除。
4. **在运行前固定比较与停止规则。** 候选数、运行次数、主指标、守护条件、故障恢复策略、预算、可接受的计划偏离都先记录。不能因官方分低而新增同题重试、删失败题或改分母；基础设施恢复另建 attempt、保留原失败，按既有协议解释。
5. **独立验证测试质量。** 合成反例应测试任务契约，不只重复实现逻辑；使用变形性质、独立参考或已知注入错误检查测试是否有检出力。红→绿是必要证据之一，但不是测试正确的充分条件。实现者不接收真实 gold，验证者也不通过反复报具体答案让它反向拟合。
6. **报告全体尝试与不确定性。** 列候选数、成功/失败/未定、费用、逐题翻转与守护结果。若样本和独立组数足够，做按来源组的配对不确定性估计；组数不足就报告描述性结果，不给虚假显著性。LLM judge 先在人工标签上校准，复核分歧，不能用另一个模型赞同替代外部证据。
7. **端到端与机制实验互补。** 固定中间态可帮助隔离某组件作用，完整 fresh run 检查系统效果；两者都保留输入身份与实际模型输出。只做端到端分差会混杂，只做固定阶段重放可能漏掉集成影响。

## 9. 来源核验、复现材料与研究限制

**本次确实阅读的核心原文**为 P1–P8 中链接的全文方法、实验和局限；P4 的大页面采用直接 HTTPS 下载后的本地文本阅读。补充表中的文献读了所列相关部分，未声称全部附录逐字精读。官方仓库核验范围主要是 README、目录、公开数据/实验入口存在性；没有逐仓库审计实现、冻结可重跑环境或运行论文实验。尤其不能把“官方代码存在”写成“已复现”。

可回访的本地检索材料放在 Git 忽略的 `var/research/agent-evaluation-20261014/`：原文 HTML、提取文本及带 URL/内容哈希的 `sources*.json`，另有 `notes.md` 记录选择与排除依据。完整论文不加入 Git；本报告的外部链接与章节定位应足够在没有 `var/` 时复查关键结论。HTML 数学公式在文本提取中可能丢失或重复，关键数值使用表格/正文交叉核对；没有将提取格式当原文语义。

主要研究限制：

- **没有 SN 机制对照实验。** 本报告证明相关研究中存在这些机制及作者报告的证据，不证明它们能提高当前 provider/模型上的 SN 改进效率。
- **论文多是不同任务与历史模型。** 软件修复、短程工具任务和合成科研任务不等于真实跨模块 RAG 算法研发；本项目需要自己的过程评测集。
- **因果证据强弱不同。** SWE-agent/Agentless 的局部消融较直接；自动科研总体成绩、多角色框架横比和失败分类更易受任务、预算、模型与主观标注影响。
- **基准与 judge 均可能有偏差。** 生成测试、LLM 自动审计和少量志愿者评分不构成完整正确性 oracle；采用它们仍需反例、保留样本和人工复核。
